# task_prd.txt — Fix cross-user cart/favorites (Option A), ensure admin login works, add Checkout page with Stripe scaffolding

## Context

* Cart and favorites are implemented with Zustand stores and partially synced with server.
* State persists across identities (anon → User A → User B) causing leakage.
* Credentials auth uses JWT sessions; Google OAuth optional.
* Admin seeding exists in `lib/data/seed.ts` but admin login is failing in practice.
* `/cart` checkout button only shows a toast; real checkout flow not implemented.

---

## Goals

1. **Option A (Minimal) isolation for client stores**

   * Prevent cross-identity leakage by clearing local cart/favorites when identity changes and switching to **pull-only** sync on login.
   * Clear client stores on sign-out.
   * (Optional) *One-time anon → user import* after login on the same device, guarded to avoid migrating data from other accounts.

2. **Admin login works**

   * Verify/repair admin seeding path. Ensure admin created from `.env` and can login with credentials.
   * Provide a separate `admin-login-guide.txt` output with step-by-step instructions (Codex must generate that file).

3. **Checkout flow**

   * Implement `/checkout` page with production-quality UI.
   * Wire **Stripe**-based card checkout scaffolding (Visa/Mastercard) up to the boundary where secrets/tokens are required.
   * Modify the Cart checkout button logic: redirect unauthenticated users to login/register; on first authenticated load, import anonymous cart (if present, same-device only, no cross-account contamination). Authenticated users go to the new Checkout page.
   * Provide a separate `Checkout-page-changes.txt` detailing what was done and what secrets/configs the user must provide.

---

## Non-Goals

* Store-level namespacing (Option B) — **do not** implement per-identity storage keys in this task.
* Full payment capture or webhooks; only scaffold up to secret-requiring API calls.

## Implementation Details

### A. Identity Guard & Pull-Only Sync (Favorites)

**Files:** `components/account/FavoritesView.tsx`

1. Add an identity guard to reset local stores when user identity changes:

```tsx
// At component top
import { useRef, useEffect } from "react";
import { useCartStore } from "@/lib/store/cart";
import { useFavoritesStore } from "@/lib/store/favorites";

const lastIdentityRef = useRef<string | null>(null);
useEffect(() => {
  const current = session?.user?.id ?? "anon";
  if (lastIdentityRef.current === null) {
    lastIdentityRef.current = current;
  } else if (lastIdentityRef.current !== current) {
    // Identity changed → wipe local-only state and force re-sync
    useFavoritesStore.getState().clear?.();
    useCartStore.getState().clear?.();
    setProducts([]);
    setHasSynced(false);
    lastIdentityRef.current = current;
  }
}, [session?.user?.id, status]);
```

2. Make sync **pull-only** when authenticated; remove the current local→server push of `ids`:

```tsx
// Replace syncFavorites block with:
useEffect(() => {
  if (status !== "authenticated" || !session?.user?.id) {
    setHasSynced(false);
    return;
  }
  if (!hasSynced) {
    (async () => {
      await loadServerFavorites(false);
      setHasSynced(true);
    })();
  } else {
    void loadServerFavorites(false);
  }
}, [status, session?.user?.id, hasSynced]);
```

3. On sign-out (see below), we clear stores proactively.

### B. Identity Guard & Checkout redirect (Cart)

**Files:** `components/cart/CartView.tsx`

1. Add the same identity guard as above (using `lastIdentityRef`).

2. Change the Checkout button handler:

   * If `status !== "authenticated"` → redirect to `/account` with `callbackUrl` to `/checkout` and set a `sessionStorage` flag `pal:import-anon-cart-once=true`.
   * If authenticated → `router.push("/checkout")`.

3. On first mount after successful login (in a small `useEffect` in `CartView` or a dedicated `CheckoutGate` client component mounted on `/checkout`):

   * If `sessionStorage.getItem('pal:import-anon-cart-once') === 'true'` and there are **local anonymous items** in the cart:

     * Call `POST /api/cart/bulk` with the list.
     * Clear the flag (`sessionStorage.removeItem(...)`).
     * Refresh cart from server.
   * This ensures anon→user import happens **only once and only for that device/session**.

## Acceptance Criteria

1. Switching identities (anon↔user, userA↔userB):

   * Local cart/favorites do **not** carry over.
   * On sign-out, local cart/favorites are cleared.
2. Logging in from anon with a non-empty local cart:

   * User is redirected to `/checkout` via `/account?callbackUrl=/checkout`.
   * A one-time import merges the **current device’s** anonymous cart into the logged-in user’s cart and then clears the import flag.
3. Favorites for authenticated user use **pull-only** sync; no local→server migration on login without explicit import.
4. Admin can be created via seed or `make:admin`, and the credentials in `.env` successfully log in.
5. `/checkout` renders with form sections, summary, and a disabled Stripe button when not configured; when Stripe keys are present, `create-payment-intent` returns a `clientSecret` and the page shows Stripe Elements.
6. `admin-login-guide.txt` and `Checkout-page-changes.txt` are generated with accurate, step-by-step content.

# admin-login-guide.txt — How admin is seeded and how to log in

1. **Configure `.env`**

```
ADMIN_EMAIL="suren.norekyan123@gmail.com"
ADMIN_NAME="Palmanhac Admin"
ADMIN_PASSWORD="Palmanhac123##AdminPass"
BCRYPT_COST="12"
```

2. **Run migrations & seed**

```bash
pnpm prisma migrate deploy     # or `pnpm prisma migrate dev` in dev
pnpm prisma db seed            # runs lib/data/seed.ts
```

> If seeding was previously skipped or email existed, also run the helper:

```bash
pnpm make:admin                # runs scripts/create-admin.ts (upsert)
```

3. **Verify admin exists**

```bash
pnpm prisma studio             # open and check User.role === ADMIN
# or SQL
# SELECT id, email, role FROM "User" WHERE lower(email)=lower('suren.norekyan123@gmail.com');
```

4. **Log in as admin**

* Open **/account** (localized path via `withLocale`), choose **Login**.
* Enter `ADMIN_EMAIL` and `ADMIN_PASSWORD`.
* On success, session’s `user.role` should be `ADMIN` (visible in dev tools or via an admin-only page guard).

5. **Troubleshooting**

* If login fails: ensure password hashing cost matches BCRYPT_COST, and no whitespace in env vars.
* If Google account existed with the same email, `upsert` still promotes to ADMIN and sets a password.

# Checkout-page-changes.txt — What was implemented & what you must configure

## Implemented

* `/checkout` page with Contact/Shipping, Billing, Payment, and Order Summary UI.
* Auth gate: unauthenticated users redirected to `/account?callbackUrl=/checkout`.
* One-time anon→user cart import on first post-login visit to `/checkout` (same-device only).
* Server totals computed securely on `POST /api/checkout/create-payment-intent`.
* Stripe scaffold: creates Payment Intent when `STRIPE_SECRET_KEY` is set; otherwise returns setupRequired flag.
* Cart and favorites identity guards and store clearing on sign-out.

## Required from you (to fully enable card payments)

1. **Stripe account & keys**

   * Add to `.env`:

```
STRIPE_SECRET_KEY=sk_test_...
NEXT_PUBLIC_STRIPE_PUBLISHABLE_KEY=pk_test_...
```

2. **Currency & amount**

   * Confirm currency (e.g., `EUR` or `USD`) in the create Payment Intent logic.

3. **Domain/redirects**

   * If using Stripe Elements: no external redirect required.
   * If later using Checkout Sessions: configure `success_url`/`cancel_url` domains.

4. **Webhooks (later)**

   * Create `POST /api/stripe/webhook` and set `STRIPE_WEBHOOK_SECRET`.
   * On `payment_intent.succeeded`: mark order as paid, capture metadata.

5. **Order persistence**

   * Ensure an `Order` and `OrderItem` schema exist; write the order draft before creating PI; update status on webhook.

6. **Testing**

   * Use Stripe test cards (e.g., `4242 4242 4242 4242`).
