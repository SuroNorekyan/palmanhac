Changes
- `lib/payments/eupago.ts`: rebuilt the EuPago client to honour `EUPAGO_API_BASE` without hard-coded suffixes, added header/body auth modes (header now sends `ApiKey`, body injects `apiKey`), switched create calls to sandbox endpoints (`POST /api/v1.02/creditcard/create`, `/api/v1.02/mbway/create`, `/clientes/rest_api/multibanco/create`), and introduced helpers for MB WAY status URLs and Multibanco info polling. `Authorization: Bearer` was removed entirely; card flows now require `EUPAGO_CARD_RETURN_URL`. 
- `lib/payments/eupago.ts`: narrowed card/MB WAY payloads to EuPago’s documented minimal schema, reinstating `value`/`currency` alongside the string `amount` and ensuring the `apiKey` is present in both headers and body; Multibanco form posts stay lean with `apiKey`, `id`, `valor`, `descricao`, `email`.
- `app/api/payments/eupago/status/route.ts`: status polling now resolves the order by `providerRef`, gates on the signed-in user, short-circuits local `PAID` orders, fetches MB WAY status via stored `statusUrl`, and optionally queries `/clientes/rest_api/multibanco/info` with body auth. Responses stay backward compatible (`{ status: { status, paidAt?, error?, raw } }`), and graceful fallbacks instruct users to wait for the webhook when metadata is missing.
- `app/api/payments/eupago/webhook/route.ts`: documented the active sandbox tunnel (`https://send-surgery-arrives-regular.trycloudflare.com/api/payments/eupago/webhook`) and the requirement to reuse the generated cryptographic key as `EUPAGO_WEBHOOK_SHARED_SECRET`.

Sandbox Test Guide
1. Card (hosted page)
   - Ensure `.env.local` contains the sandbox values from task8Eupago_prd.txt plus `EUPAGO_CARD_RETURN_URL="http://localhost:3000/orders"`.
   - In checkout pick products totalling ≥ €500, select Card, and submit. You should receive `{ paymentUrl, transactionId }`.
   - Follow the redirect and use EuPago’s sandbox Visa (`4543630000000000`, expiry `12/29`, CVC `123`). When prompted for 3-D Secure, submit the test OTP `1234`.
   - After the hosted flow completes you should land on `/orders`; when the webhook arrives the order transitions to `PAID`.
2. MB WAY
   - Start a checkout with MB WAY, supplying the sandbox alias `911234567`.
   - Confirm the UI enters polling (`/api/payments/eupago/status?transactionId=...`) and displays “awaiting approval”.
   - Approve the push in the MB WAY sandbox app (or trigger a webhook with status `paid`). The order should flip to `PAID`, cart clears, and you remain on `/orders`.
3. Multibanco
   - Choose Multibanco in checkout; record the entity, reference, and expiry returned to the UI.
   - Call EuPago’s sandbox payment simulator (or ask support) to mark the reference as paid. The webhook should deliver to the tunnel URL and mark the order `PAID`.
   - If you need to poll manually, `GET /api/payments/eupago/status?transactionId=<reference>` now calls `/clientes/rest_api/multibanco/info` using body auth and returns the normalised status.
4. Negative paths
   - Submit an invalid MB WAY alias to confirm the create route surfaces the provider error.
   - Cancel the card flow at EuPago to ensure the webhook captures `failed/cancelled` and the order stays unpaid.

Go Live Checklist
- Update environment variables:  
  `EUPAGO_API_BASE="https://clientes.eupago.pt"`  
  `EUPAGO_API_KEY="<production API key>"`  
  `EUPAGO_WEBHOOK_SHARED_SECRET="<production cryptographic key>"`  
  `EUPAGO_CARD_RETURN_URL="https://<live-domain>/orders"`
- In EuPago backoffice (production), enable the required payment methods (Card, MB WAY, Multibanco) and point Webhooks 2.0 to `https://<live-domain>/api/payments/eupago/webhook` using the matching cryptographic key.
- Confirm the return URL configured in EuPago’s hosted payments matches `EUPAGO_CARD_RETURN_URL`.
- Re-run the card, MB WAY, and Multibanco smoke tests against the live environment before launch.

Known Caveats
- EuPago sandbox webhooks can lag several minutes; the status route now falls back to “pending” with guidance when reference metadata is missing.
- Multibanco info polling depends on EuPago exposing the reference; if the sandbox omits it, rely on webhook completion instead.
- The legacy documentation in `eupago-guide.txt` still references the deprecated `/api` suffix—update it when you next revise the guide.
