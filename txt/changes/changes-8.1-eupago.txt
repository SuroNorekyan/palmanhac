Updates
- `lib/payments/eupago.ts`: expanded authentication to send `Authorization: ApiKey <key>`, `ApiKey`, and `X-Api-Key` headers for header-mode calls, while still stuffing `apiKey` into JSON payloads as a fallback. Multibanco helpers now submit `application/x-www-form-urlencoded` payloads containing only EuPago’s accepted fields (`apiKey`, `id`, `valor`, `descricao`, optional `currency`/`email`), enforce a ≥€1.00 amount, and reuse the same form encoding for `/clientes/rest_api/multibanco/info`. MB WAY status polling also gained the new header trio.
- Simplified card/MB WAY payloads to the schema EuPago documents (`value`/`amount` numeric plus `valor` string) to eliminate `AMOUNT_MISSING` while still providing required metadata.
- Introduced non-production console debug logs to inspect EuPago request payloads (API key redacted) for troubleshooting.
- Added development-only logging in `/api/payments/eupago/create` to trace method, order ID, and totals when spinning up payments.
