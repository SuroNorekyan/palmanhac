Fix summary
- Updated `lib/data/seed.ts` to import the mock item parser via a relative path so Prisma’s seeding CLI no longer relies on the Next.js `@` alias (which isn’t available to `ts-node` in ESM mode).
- Adjusted the parser import to use the TypeScript source directly (`./mockItemParser.ts`), letting `ts-node` resolve the module without extra tooling.
- Confirmed that `docker-compose.yml` exposes Postgres on `localhost:5433` and matches the `.env` `DATABASE_URL`.

Startup & verification checklist
1. Ensure Docker Desktop is running, then start the database: `docker compose up -d`.
2. Install dependencies if needed: `pnpm install`.
3. Generate the Prisma client: `pnpm prisma generate`.
4. Apply the latest schema (creates the `Product` table): `pnpm prisma migrate deploy` (or `pnpm prisma migrate dev` during local development).
5. Seed the database with the 10 catalog products: `pnpm prisma db seed`.
6. (Optional) open Prisma Studio to inspect the rows on http://localhost:5555: `pnpm prisma studio`.
7. Launch the Next.js app and confirm product listings at http://localhost:3000: `pnpm dev`.

Troubleshooting notes
- If seeding fails with `ERR_MODULE_NOT_FOUND`, double-check the local changes above and re-run `pnpm prisma db seed`.
- Connection errors usually mean the container is not ready yet; re-run `docker compose ps` to confirm `palmanhac-postgres` is `Up` and listening on `0.0.0.0:5433`.
- Prisma Studio reads the same `DATABASE_URL`, so once steps 1–5 succeed you’ll see all 10 products there.
