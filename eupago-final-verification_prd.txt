# Goal: Ensure the entire payment system is fully correct and production-safe

## Overview

This PRD instructs Codex to perform a **full verification and correction pass** across the entire Palmanhac EuPago integration.

The purpose is to confirm that **MB WAY**, **Multibanco**, and **Card** payment flows are now fully consistent with the official EuPago production APIs, and that the frontend and backend accurately reflect the live payment status in real time for both:

- Customers (logged-in)  
- Admin users

# Part 1 — Official EuPago Flows That Must Be Verified

Codex must check that the system supports **all three routes of receiving payment status**:

## 1. MB WAY Webhook (Webhooks 2.0)
Triggered instantly when the user approves MB WAY payment.

Codex must verify:

- Webhook signature verification logic is correct (`EUPAGO_WEBHOOK_SHARED_SECRET`)
- The webhook route correctly parses:
  - `transactionId`
  - `reference`
  - `identifier`
  - new `transactions[]` payload structure
- The route updates:
  - `paymentStatus` to `"PAID"`
  - `paidAt`
  - order history events
- Email confirmation is sent using `sendPaymentConfirmationEmails`

---

## 2. MB WAY "statusUrl" (if EuPago returns one)
Many live MB WAY responses contain a `statusUrl`.

Codex must verify:

- The `/api/payments/eupago/status?transactionId` logic checks:
  - `statusUrl` first
  - Falls back to references-by-status if missing  

This logic currently exists — Codex must ensure it is fully correct.

---

## 3. MB WAY + Multibanco References-by-Status fallback (Bearer token)
Codex must confirm:

- OAuth token generation using:
  - `EUPAGO_OAUTH_CLIENT_ID`
  - `EUPAGO_OAUTH_CLIENT_SECRET`
  - `EUPAGO_OAUTH_GRANT_TYPE=client_credentials`
- The app internally calls:
  `/api/management/v1.02/references`
- The returned structure matches what the backend expects
- Status normalization:
  - `"paga"` → `"paid"`
  - `"pendente"` → `"pending"`
  - `"expirada"` → `"expired"`
  - `"cancelada"` → `"cancelled"`  
- Correct handling of:
  - `identifier`
  - `reference`
  - `datetime`

Codex must verify that **lookupReferenceStatus()** matches the real EuPago structure.
