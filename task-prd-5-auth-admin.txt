1) Authentication & Authorization (Modern + Secure)
1.1 Auth Stack

Use Auth.js (NextAuth) with Route Handlers.

Providers:

Email/password (credentials) with strong password policy, bcrypt hashing.

Google OAuth (Provider).

Sessions: secure cookies (HTTPOnly, SameSite=Lax or Strict where possible), short access token lifetime + rolling session.

CSRF: use Auth.js’ built-ins.

Rate limiting for sign-in attempts (e.g., middleware-level simple limiter).

1.2 Prisma Models (extend/update)

Add/adjust to include:

User { id, email (unique), name, role ('USER' | 'ADMIN'), image?, passwordHash?, twoFAEnabled (bool), twoFASecret?, recoveryCodes? }

Account, Session, VerificationToken (Auth.js standard models).

Product (existing), Order, OrderItem, Favorite:

Order { id, userId, status, totalAmount, paymentStatus, createdAt }

OrderItem { id, orderId, productId, quantity, unitPrice }

Favorite { id, userId, productId, createdAt } (unique compound index on userId+productId)

Keep current project conventions; only add what’s missing. Run necessary Prisma migrations and minimal seed.

1.3 Roles & Guards

Role-based access control:

USER: can manage account, view orders, add/remove favorites.

ADMIN: full CRUD for catalog (products), and order management endpoints.

API/route protection:

Server-side guards on every admin route/handler (deny by default).

Client-side redirect helper if not admin (defense in depth).

Avoid leaking admin UI to non-admins (conditional render + server checks).

2) Admin-Only Area (+ TOTP 2FA)
2.1 Admin Credentials & Seeding

Create a single seed admin with:

role = 'ADMIN'

A strong random password (store hash in DB; do not commit plaintext).

Environment variables to override admin email on boot: ADMIN_EMAIL, ADMIN_NAME (optional).

2.2 TOTP 2FA (Google Authenticator compatible)

Use otplib (or speakeasy) to generate a TOTP secret for the admin only in this iteration.

Store twoFASecret (encrypted at rest or at least base32 stored with care) and twoFAEnabled boolean.

Enrollment flow (admin only):

Visit /admin/2fa/setup (protected).

Generate secret + otpauth:// URI; render QR (e.g., qrcode lib).

Admin scans in Google Authenticator.

Admin enters current 6-digit code → if valid, mark twoFAEnabled=true and persist secret.

Show one-time recovery codes (store hashed; allow regeneration).

Sign-in flow (admin):

After password/OAuth success, if twoFAEnabled, present a second step for TOTP.

Deny access to /admin without a valid second factor in the session.

2.3 Step-by-Step: Connect Google Authenticator (for the Admin)

Include the following guide in docs/admin-2fa-setup.md:

Navigate to /admin/2fa/setup.

Click Generate Secret, scan QR with Google Authenticator.

Enter the 6-digit code to verify and enable 2FA.

Save recovery codes securely; they can be used if the device is lost.

Next sign-in will prompt for the TOTP code (or a recovery code).
